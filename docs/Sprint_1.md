# SoundCount: Спринт 1 — Инженерная Архитектура и Технический Пайплайн

Документ описывает техническую реализацию, библиотечный стек, устройство конвейера обработки звука и архитектуру веб-дашборда визуализации Спринта 1.

---

## 🛠️ 1. Технологический Стек и Библиотеки

- **`librosa`** (Python): Препроцессинг аудио, вычисление матриц Constant-Q Transform (`librosa.cqt`) и логарифмирование амплитуды в децибелы (`librosa.amplitude_to_db`).
- **`soundfile` / `scipy.io.wavfile`** (Python): Загрузка необработанных PCM данных `.wav`/`.mp3`, конвертация стерео каналов в моно и нормализация отсчетов на интервал $[-1.0, 1.0]$.
- **`numpy`**: Векторизованные математические вычисления `Spectral Flux` (разности `np.diff`, фильтрация `np.maximum`, статистика скользящего окна).
- **`http.server` / `socketserver`**: Встроенный сервер Python для раздачи статического фронтенда и JSON-данных на `http://localhost:3000` (`allow_reuse_address = True`).
- **HTML5 Canvas 2D / WebAudio API / ES6 JavaScript**: Клиентская часть визуализатора без внешних фреймворков, работающая в честных 60 FPS через `requestAnimationFrame`.

## 🏗️ 2. Архитектура и Поток Данных (Data Pipeline)

Обработка аудиофайла до отображения на клиенте проходит 6 этапов:

```
data/input/ (.mp3 / .m4a)
       │
       ▼
[src/preprocessing/ingest.py] ──> Декодирование в моно 22050 Гц, PCM normalisation [-1, 1]
       │
       ▼
[src/parsing/cqt.py] ───────────> 84-биновая CQT спектрограмма C[k, m] (C1–C8, 12 полутонов)
       │
       ▼
[src/novelty/spectral_flux.py] ──> 4-полосный Spectral Flux + 3s скользящая нормализация + adaptive peak picker
       │
       ▼
[visualization/data_exporter.py] ─> Экспорт структуры в visualization/public/analysis.json
       │
       ▼
[visualization/server.py] ──────> HTTP статика + стриминг аудио на http://localhost:3000
       │
       ▼
[visualization/public/app.js] ──> 60 FPS Canvas UI (Heatmap + Multi-Band Flux + Dynamic Slice Bar + 4-Lane Piano Tiles)
```

### Структура Выходного Файла `analysis.json`
Модуль экспорта формирует оптимизированный JSON-пакет для фронтенда:
- `fps`: Нормированная частота кадров анализа ($f_s / H \approx 43.06$ кадров/сек).
- `spectrogram`: 2D-матрица амплитуд CQT размерности $K \times M$ ($84 \times M$).
- `flux_bands`: Массив из 4 нормализованных кривых новизны для полос Бас, Тенор, Альт, Сопрано.
- `attacks`: Массив точных временных меток атак $T_{\text{attacks}}$ в секундах.

## ⚡ 3. Инженерные Решения Клиентской Визуализации (60 FPS UI)

### 3.1. Синхронизация Времени через `requestAnimationFrame`
Стандартное событие HTML5 `<audio>` `timeupdate` обновляет время с частотой 1–4 Гц, что вызывает сильные микро-дергания. Для плавности 60 FPS отрисовка отвязана от `timeupdate` и выполняется через цикл `requestAnimationFrame`, который непрерывно считывает микросекундные часы `audioPlayer.currentTime`.

### 3.2. Динамический Срез Спектра (Time-Slice Vector)
Для считывания спектра кадра в текущий момент времени $t$ вычисляется индекс кадра $m(t)$:

$$m(t) = \left\lfloor \frac{t \cdot f_s}{H} \right\rfloor$$

Вектор $\vec{V}(t) = \big( S(m(t), 0), \dots, S(m(t), 83) \big)$ отрисовывается в виде 84-столбчатого эквалайзера (Live Slice Bar Chart) синхронно со звуком.

### 3.3. Кэширование Текстур через Offscreen Canvas
Рендеринг крупной 2D CQT-спектрограммы ($84 \times M$ пикселей) непосредственно в основном цикле 60 FPS создает высокую нагрузку на GPU/CPU. 

1. Спектрограмма и кривые новизны отрисовываются во вспомогательный буфер `offscreenCanvas` **один раз** при загрузке трека.
2. В основном цикле выполняется единственная операция `ctx.drawImage(offscreenCanvas, ...)` с последующей легкой отрисовкой линии плавающего курсора времени (Playhead), уменьшая время кадра до $< 1$ мс.

### 3.4. Просмотрщик Piano Tiles (Right-to-Left Scrolling)
Игровая область размечает 4 горизонтальные дорожки. Координата попадания плитки в таргет — $X_{\text{hit}} = 90$ px. Положение плитки с временем появления $t_{\text{peak}}$ при 3-секундном горизонте планирования вычисляется как:

$$X(t_{\text{peak}}, t) = X_{\text{hit}} + \left( \frac{t_{\text{peak}} - t}{3.0} \right) \cdot (W - X_{\text{hit}})$$

При достижении линии таргета ($\Delta t \approx 0$) запускается анимация радиального ореола удара (Hit Burst Glow).
